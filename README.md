# Echo 回响 · 演出导购

独立的演出发现、观众口碑与选票助手，适配 Echo 回响在线票务平台。

## 一键打开

双击 `start-guide.cmd`，访问 **http://127.0.0.1:8082**。

先执行一次 `build-guide.cmd` 生成导购程序与网页，再双击 `start-guide.cmd`。请先确保 Echo 后端 `127.0.0.1:8081` 与 Echo 用户页面 `127.0.0.1:3002` 正常运行。

## 用户端（导购页）

- 演出列表：公开演出分页、历史回顾、全站观众评测、精确均分与星级分布、综合口碑排行、收藏与 2–4 场对比。详情票档带秒杀倒计时（距开抢 / 距结束）。
- 筛选：城市、类型、日期、评分、预算、余票，同步到地址栏参数，刷新和分享都保留视图。城市只保留真实城市，香港、澳门、台湾显示为中国香港、中国澳门、中国台湾。
- 口碑排序：先按有效评分数量分层（≥5、3–4、2、1、无评分），同层内再按样本修正分排序，少量五星不会压过样本更多的演出；显式选「评测均分」时仍按均分。
- 选票助手：流式回答——真实数据的推荐与回答先逐段出现，模型随后接续润色，模型慢或失败不影响先看到结果；推荐条目带评测高频关键词与与提问相关的评测原文引用。记住人数、总预算、日期与座位偏好；条件过窄时说明是哪项限制导致无结果，并给出最多 2 条带标注的备选。
- 购票闭环：票档按钮按已记住的需求生成确认链接（人数 / 预算 / 座位偏好带入详情页），选好后前往 Echo（`127.0.0.1:3002/guide`）完成确认订单、付款与评测发布。

## 选票 Agent（多步推理）

选票助手不是「一次模型调用」，而是一个能规划、能调工具、能写数据的 Agent：

- **五段流水线**：规划意图 → 调用工具 → 观察结果 → 组织答案 → 自检回退；
- **8 个工具**：`search_shows`（检索）、`show_detail`（票档）、`list_reviews`（评测原文）、`compare_shows`（并排对比）、`venue_tips`（观演常识库）、`budget_plan`（预算计算器），以及两个写工具 `add_watchlist`（加入观演清单）、`save_preference`（记住长期偏好）；
- **写操作三步走**：提案 → 人工确认 → 执行。模型只能生成待确认动作，真正落库必须由用户点「确认执行」；重复确认返回 409 而不是重复写入；
- **双引擎**：配了模型走 ReAct（模型自己编排工具，支持一轮并行 2–3 个互不依赖的调用并去重），没配模型走规则编排，两条路径共用工具、记忆与轨迹；
- **多轮记忆 + 长期偏好**：会话级 Slots 30 分钟过期；设备级偏好（城市/类型/预算/座位）确认后持久化，下一轮自动带上，用户明确说的条件永远优先；
- **上下文压缩**：决策前超过 6000 字就把早期观察压成工具摘要（确定性规则，不是再调一次模型）；
- **全程可见**：每一步实时推给前端，聊天里可展开「N 步推理」时间线；写操作有独立确认卡片；
- **断点续跑**：每步推理落快照（决策上下文 + 已查事实），超时或断连的运行可按 `run_id` 接着跑，已查到的结果不重查，重启后依然有效；
- **可审计**：运行轨迹落 `agent-runs.jsonl`，写操作审计落 `agent-state.json`，管理端可按 `run_id` / 动作编号回查；
- **可跑分**：`POST /api/v1/guide-admin/agent/bench` 用 8 条固定用例回放，输出意图准确率、工具命中率、平均步数与耗时；
- **有护栏**：工具白名单、最多 4 步、单步 20 秒、总量 75 秒、观察截断；答案自检发现「已下单/已支付/已锁座」一律回退数据版回答；
- **观演常识走向量检索**：12 条常识建向量索引，向量召回 + 词面重排双阶段；没有模型 Key 时用离线 n-gram 向量，质量不降级；管理端可在 15 条标注问题上对比三种策略的召回率。

入口：`POST /api/v1/ticketing/agent`（JSON）、`POST /api/v1/ticketing/agent/stream`（SSE）；
写操作：`POST /api/v1/ticketing/agent/actions/{id}/confirm|reject`；
续跑：`POST /api/v1/ticketing/agent/resume/{run_id}`（`/stream` 为 SSE）。

## 助手管理端（#admin）

在 `guide.env.cmd` 里设置 `GUIDE_ADMIN_TOKEN`（建议长随机串）后，导购页页脚出现「导购管理 ↗」，或直接打开 **http://127.0.0.1:8082/#admin**。未设置口令时不显示入口，管理接口返回 503；口令只保存在环境变量与当前浏览器标签页，模型 API Key 不会返回给页面。

功能分七块：

1. **助手概览**：演出覆盖、可购场次、评分与评测数量、重启后咨询量、模型回退次数。
2. **数据健康**：逐条点名问题——评分样本偏少、无评分、票档缺失、退改规则缺失、异常低价票档。
3. **质量巡检**：内置 7 条固定需求 + 管理员自定义用例（问题 + key=value 期望），关闭模型、逐条给出判断依据。
4. **城市数据**：按城市汇总演出、可购、有效评分与均分、评测、票价区间、票档与需选座，缺票档 / 评测不全的城市单独标出；含类型分布。
5. **票种与票档**：汇总可售 / 售罄 / 秒杀 / 选座 / 快照库存 / 缺退改规则 / 异常低价 / 余票与均价，价格带占比，逐档明细支持搜索、城市、价位、只看可售、只看需留意五种筛选。
6. **对话试验台**：按访客原话提问验证解析与回答；也可直接问数据缺口（走确定性统计不调模型）。多轮沿用上一条需求，历史保存在当前标签页；「调用模型」开关默认关闭。
7. **数据草稿**：粘贴演出描述，模型生成演出 + 票档草稿并可导出 CSV（不写入 Echo）。另有城市/票档表格一键导出 CSV；概览健康项数量以红色徽章显示在导航；咨询统计落盘重启不丢；最近请求超长问题可展开。

其余管理能力：**提示词管理**：查看 / 编辑助手提示词，保存自动升版本落盘 `backend/guide-prompt.json` 并立即生效；保存、恢复默认与回滚需再次输入管理口令确认，每次改动记入修改记录（可回滚）并自动跑一遍质量巡检；60–8000 字校验。

另有**最近请求**表：最近 20 条咨询的问题、回答模式、推荐与备选数、耗时。

## 仓库结构

```text
backend/cmd/guide/      进程入口：API、SSE、静态页托管、优雅退出
backend/src/agent/      Agent 运行时：规划、工具编排、记忆、自检、轨迹
backend/src/guide/      导购业务：筛选/口碑/需求解析/对比/SSE/管理端
backend/src/ticketing/  Echo 只读数据适配器：HTTP 优先、MySQL 只读降级
backend/src/llm/        OpenAI 兼容模型客户端：只做润色与草稿
frontend/               React 19 + Vite 前端源码与构建产物
docs/ECHO-GUIDE.md      Echo 接口契约、字段口径与 Agent 协议
start-guide.cmd         一键启动（自动读取 guide.env.cmd）
build-guide.cmd         重建后端可执行文件与前端产物
guide.env.example.cmd   环境变量样例，复制为 guide.env.cmd 后填写
```

一句话说明数据流：`ticketing` 取数 → `agent` 规划并调用工具 → `guide` 还原成票务卡片 → `llm` 润色（可缺席） → 浏览器。
导购不写 Echo 的数据库，也不持有 Echo 用户令牌；Agent 的写操作只落在本地 JSON，且需用户确认后才生效。

## 配置和开发

- 地址与模型设置：参考 `guide.env.example.cmd`，本地配置放在 `guide.env.cmd`（含 `GUIDE_ADMIN_TOKEN`）。
- 没有模型配置时仍可浏览演出和票档，并获得基于票务数据的选票建议；助手管理端的所有功能在无模型时同样可用（巡检与对话台本来就不调模型）。
- 重建：运行 `build-guide.cmd`（前端 `build:direct` + 后端 `go build`）。
- 测试：`cd backend && go test ./...`；真实 Echo 联调加 `TICKETING_INTEGRATION_TEST=1`。
- 开发前端默认 `127.0.0.1:5174`，导购服务默认 `127.0.0.1:8082`。
- 接口清单、字段口径与 SSE 协议：[Echo 对接与数据约定](docs/ECHO-GUIDE.md)。

## 项目边界

本项目负责演出发现、口碑比较、选票建议、评测草稿与助手管理端。下单、付款、评测发布由 Echo 票务主站完成：用户在 Echo 选座并确认订单后才执行下单，付款单独确认，评测预览后确认发布。导购后端不持有 Echo 用户令牌，也不直接调用交易写入接口。Echo 当前付款为模拟支付。
